# Система аутентификации и авторизации, с разграничением прав к ресурсам

Данный проект представляет собой backend-приложение на Django, реализующее систему аутентификации и авторизации.
В проекте разработаны как REST API, с использованием Django REST Framework, так и веб-интерфейс на Django Templates.
Система позволяет управлять пользователями, ролями и правами доступа к ресурсам, реализованным в проекте (продукты,
заказы, пользователи и т.д.).

## Описание проекта

Проект реализует систему аутентификации и авторизации, с механизмом разграничения прав доступа.
Основная идея – гибкое назначение прав на выполнение операций (чтение, создание, обновление, удаление) над
определёнными ресурсами, в зависимости от роли пользователя.

### Модели, используемые в проекте:

* User (кастомная модель пользователя)
* Role (роль пользователей)
* Element (бизнес эл-т проекта. Например: продукты, заказы, ...)
* AccessRolesRules (права доступа для ролей и эл-в)

Для тестирования проекта, присутствует [кастомная команда](#load_test_data), для добавления предопределенных данных в проект.
Ниже описаны объекты, которые добавляет данная команда.

### Роли:

* admin
* manager
* user
* guest

### Элементы (ресурсы):

* users (пользователи)
* products (продукты)
* orders (заказы)
* roles (роли)
* permissions (права, описанные в AccessRolesRules)
* elements (сами бизнес эл-ты)

Для простоты, роли и эл-ты проекта ограничены теми, которые указаны выше.

Права задаются через модель AccessRolesRules, связывающую роль, ресурс и набор разрешений.

### Права:

| Роль    |   Элемент   | read_all_permissions | create_permissions | update_all_permissions | delete_all_permissions |
|---------|:-----------:|---------------------:|-------------------:|-----------------------:|-----------------------:|
| admin   |  elements   |                 True |               True |                   True |                   True |
| admin   | permissions |                 True |               True |                   True |                   True |
| admin   |    roles    |                 True |               True |                   True |                   True |
| admin   |    users    |                 True |               True |                   True |                   True |
| admin   |   orders    |                 True |               True |                   True |                   True |
| admin   |  products   |                 True |               True |                   True |                   True |
| manager |  elements   |                 True |               True |                   True |                   True |
| manager |   orders    |                 True |               True |                   True |                   True |
| manager |  products   |                 True |               True |                   True |                   True |
| user    |  products   |                 True |               True |                   True |                  False |
| guest   |   orders    |                 True |              False |                  False |                  False |
| guest   |  products   |                 True |              False |                  False |                  False |

* admin - полный доступ ко всем ресурсам
* manager - полный доступ к products, orders, elements
* user - доступ к products, без возможности удаления
* guest - доступ только к просмотру products и orders

Если у соответсвующей роли, у прав read_all_permissions, update_all_permissions, delete_all_permissions, присвоено
значение False, то у данной роли, есть доступ только к своим объектам. Например, если у роли user, следующие права

| Роль | Элемент  | read_all_permissions | create_permissions | update_all_permissions | delete_all_permissions |
|------|:--------:|---------------------:|-------------------:|-----------------------:|-----------------------:|
| user | products |                False |               True |                  False |                  False |

то пользователь может создать объект Product, при этом, у него будет полный доступ к нему (P.S. у объекта Product должно
быть поле owner.
Данному полю должен быть присвоен пользователь, который создал данный объект. Данный комментарий не относится к модели
User. Для данной модели,
доступ будет и без поля owner). Доступа на чтение, изменение, удаление чужих объектов у него отсутствует.

Если в таблице отсутствуют права для какой-либо пары **_роль:элемент_**, то для данной **_роли_**, нет доступа
к **_элементу_**. Например, в вышеуказанном примере, отсутствует пара **_guest:elements_**.
Соответственно, у роли **_guest_** нет ни одного доступа к элементу **_elements_**.

## Использование API

API доступно по адресу http://127.0.0.1:8000/api/. Все эндпоинты, кроме полученея токенов и регистрации, закрыты авторизацией.
Для доступа к защищённым ресурсам требуется JWT-токен.

### Аутентификация (JWT)

| Метод |         URL         |                                                                  Описание | 
|-------|:-------------------:|--------------------------------------------------------------------------:|
| POST  |     /api/token/     |                                        Получение access и refresh токенов |
| POST  | /api/token/refresh/ | Получение access токена,<br/>с использованием действующего refresh токена |

Далее токен передаётся в заголовке: Authorization: Bearer <access_token>.

### Эндпоинты пользователей

| Метод     |              URL               |                                                               Описание | 
|-----------|:------------------------------:|-----------------------------------------------------------------------:|
| POST      |         /api/register/         |   Регистрация пользователя (по умолчанию,<br/>присваивается роль user) |
| GET       |          /api/users/           |                                                   Список пользователей |
| GET       |         /api/users/me/         |                                 Просмотр профиля авториз. пользователя |
| PUT/PATCH |         /api/users/me/         |                                Изменение профиля авториз. пользователя |
| DELETE    |         /api/users/me/         |                                 Удаление профиля авториз. пользователя |
| POST      | /api/users/me/change_password/ |                                     Смена пароля авториз. пользователя |
| GET       |       /api/users/\<pk>/        |                                    Просмотр профиля пользователя по pk |
| PUT/PATCH |       /api/users/\<pk>/        |                                   Изменение профиля пользователя по pk |
| DELETE    |       /api/users/\<pk>/        |                                    Удаление профиля пользователя по pk |

P.S. При удалении пользователя, не происходит удаление обекта из БД. Поле is_active меняет значение с True на False.

### Описание оснвоного права, используемого в контроллерах, для разграничения прав
<a name="analog"></a>
Контроллеры используют класс-право CanAccessObject, описанное в модуле [permissions.py](api/permissions.py).
Экземпляр класса принимает аргумент, в зависимости от сущности контроллеров, к которым применяется. Например,
для контроллеров работы с объектами Role, вызов данного экземпляра класса, будет выглядеть
```python
CanAccessObject(object='roles')
```
Значение object - это название объекта в таблице Element.

## Использование веб-интерфейса

Веб-интерфейс использует стандартные Django-шаблоны и сессионную аутентификацию.

### Аутентификация и управление профилем

* /login/ – вход
* /logout/ – выход
* /register/ – регистрация (по умолчанию, присваивается роль user)
* /password-change/ – смена пароля авторизованного пользователя
* /my_profile/edit/ – редактирование профиля авторизованного пользователя
* /my_profile/disable/ – удаление аккаунта авторизованного пользователя

### Управление пользователями

* /users/ – список пользователей
* /users/create/ – создание нового пользователя
* /users/\<pk>/update/ – редактирование пользователя
* /users/\<pk>/delete/ – удаление пользователя

### Управление ролями

* /roles/ – список ролей
* /roles/create/ – создание роли
* /roles/\<pk>/update/ – редактирование роли
* /roles/\<pk>/delete/ – удаление роли

### Управление правами доступа

* /permissions/ – список прав
* /permissions/create/ – создание права
* /permissions/<pk>/update/ – редактирование прав
* /permissions/\<pk>/delete/ – удаление прав

### Управление продуктами и заказами

* /products/ – список продуктов
* /products/create/ – создание продукта
* /products/\<pk>/update/ – редактирование продукта
* /products/\<pk>/delete/ – удаление продукта
* /orders/ – список заказов
* /orders/create/ – создание заказа
* /orders/\<pk>/update/ – редактирование заказа
* /orders/\<pk>/delete/ – удаление заказа

**P.S. Эндпоинты продуктов и заказов (также, как в API) не работают с объектами моделей и не взаимодействуют с БД.
Эндпоинты возвращают явно заданные значения, для возможности проверки прав доступа. При удалении пользователя,
не происходит удаление обекта из БД. Поле is_active меняет значение с True на False. В модуле
[permissions.py](users/permissions.py) описан [аналог права](#analog) CanAccessObject для применения в контроллерах.**

## Установка и настройка
* Склонируйте репозиторий
```bash
git clone git@github.com:SergeyGorohov1/Auth_with_role_system.git .
```
* Создайте и активируйте виртуальное окружения 
```bash
python -m venv .venv
source .venv/bin/activate      # для Linux/macOS
.venv\Scripts\activate         # для Windows
```
* Установите необходимые зависимости
```bash
pip install -r requirements.pip
```
* Создайте и заполните файл с переменными окружения (.env) в корне проекта, на основе шаблона переменных окружения .env.template
* Примените миграции
```bash
python manage.py migrate
```
* При необходимости, создайте суперпользователя
```bash
python manage.py createsuperuser
```
<a name="load_test_data"></a>
* Запустите кастомную команду, для добавления тестовых данных в БД
```bash
python manage.py load_test_data
```
* Запустите сервер
```bash
python manage.py runserver
```

Часть приложения, реализованная с использованием шаблонов django, носит тестирующий характер и реализована для 
проверки функционала с использованием веб-интерфейса. Проект, состоящий только из api части, располагается
в ветке [feature/task-api](https://github.com/SergeyGorohov1/Auth_with_role_system/tree/feature/task-api).

Для тестирования api части, приложена [коллекция](Test_task.postman_collection.json) postman.
